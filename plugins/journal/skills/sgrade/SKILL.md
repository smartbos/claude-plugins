# S등급 코칭 스킬

인사평가 S등급 달성을 위한 **웜블러드 행동 원칙 (8 + 2)** 기반 회고 및 코칭. (2026-05-04 게시; 이전 12 core competency 매트릭스는 폐기)

## 트리거

- `/sgrade` 또는 `/회고` → 데일리 회고
- `/sgrade weekly` 또는 `/주간회고` → 주간 회고

## 시간대

**중요**: 모든 날짜/시간은 KST(한국 표준시, UTC+9) 기준.

```bash
TZ='Asia/Seoul' date '+%Y-%m-%d %H:%M %a'
```

### 저널 파일 탐색

저널 루트가 고정이므로 `.claude/journal.local.md` 캐시·discovery 불필요. 파일 자체는 재정리 진행 정도에 따라 위치가 섞여있을 수 있어 다음 순서로 찾는다:

1. **이번 달이면 루트 직접 확인**: `~/obsidian/sb/데일리 노트/YYYY-MM-DD 요일.md`
2. 없으면 `~/obsidian/sb/데일리 노트/YYYY/YYYY-MM-DD 요일.md`
3. 없으면 `~/obsidian/sb/데일리 노트/YYYY/MM/YYYY-MM-DD 요일.md`
4. 그래도 없으면 fallback:
   ```bash
   find ~/obsidian/sb/"데일리 노트" -name "YYYY-MM-DD *.md" 2>/dev/null | head -1
   ```
5. 회고 대상인데 파일이 아예 없으면 → **새로 생성** (루트에 `YYYY-MM-DD 요일.md`로, frontmatter는 비워두고 `# 주간 팀 업무`, `# 오늘 목표`, `# 감사`, `# 재미` 섹션만)

요일 한글 변환 (셸 LANG 의존하지 말 것):

```bash
WEEKDAY_EN=$(TZ='Asia/Seoul' date '+%a')   # Mon, Tue, ...
case "$WEEKDAY_EN" in
  Mon) WEEKDAY_KO="월요일";;
  Tue) WEEKDAY_KO="화요일";;
  Wed) WEEKDAY_KO="수요일";;
  Thu) WEEKDAY_KO="목요일";;
  Fri) WEEKDAY_KO="금요일";;
  Sat) WEEKDAY_KO="토요일";;
  Sun) WEEKDAY_KO="일요일";;
esac
```

## 웜블러드 행동 원칙 프레임워크

> 원본: `~/obsidian/sb/PARA-2.Area/웜블러드/웜블러드 행동 원칙.md`

### 핵심 가치 (3축)
- **신의(信義)** — 어떠한 어려움도 함께 극복하는 믿음과 의리로 One Team 완성
- **몰입(沒入)** — 최고의 성과는 강한 집중을 통해서만 나온다
- **완결(完結)** — 목표 도달 과정의 노력과 헌신을 의미 있게 한다

### 행동 원칙 (8개)

| 가치 | 원칙 | 핵심 |
|------|------|------|
| 신의 | **Align, Disagree & Commit** | 방향 서포트 + 공개 반대 + 결정 후 빠른 헌신. 뒤에서 흔들지 않음 |
| 신의 | **Feel the Customer** | 요청 기다리지 않음. 비즈니스 임팩트 큰 문제 먼저. 공감 → 즉각 착수 |
| 몰입 | **Own the Vision** | 자기 언어로 번역해 오늘의 행동으로. 우리가 만든 것 직접 써보기 |
| 몰입 | **Solve the Right Problem** | 무엇을 풀지가 먼저. 분해해서. 시간·비용·효과 균형의 practical 솔루션 |
| 몰입 | **Start Early, Learn as You Go** | 모른 채 시작하기. 30% 정보로 움직임. 결과에서 다음 정보 |
| 완결 | **Count the Outcome** | 시간/투입 아닌 Business Impact. 바쁨 ≠ 생산성 |
| 완결 | **Close with Impact** | "충분함" 판단 능력. 작게 쪼개기. 끝까지 주시 (떠넘기지 않음) |
| 완결 | **Leave It Better** | 보이스카우트 룰. 다음 완결을 더 빠르고 좋게 만드는 한 번의 완결 |

### Spirit (2개)
- **Relentless 불굴** — 위협을 자원으로 전환. 환경 탓 대신 "내 가정 어디가 틀렸나" 먼저. 결과로 말함
- **Pursue Excellence 탁월** — 완벽주의 ≠ Excellence. 빠르게 닫되 품질 비타협. Double-loop learning. 자신의 지식 경계 인식

## 현석님 행동 원칙 프로필

**자연스럽게 잘하는 (강점, 유지·증폭)**:
- **Own the Vision** — 의미 이해되면 자기 언어로 번역해서 끝까지
- **Pursue Excellence** — 호기심 + 지식 경계 인식, Double-loop 학습
- **Align, Disagree & Commit (협력 측면)** — 팀 방향 정렬에 능함
- **Leave It Better** — 코드·문서·프로세스 정리 본능

**의식적으로 개발 중 (성장 영역)**:
- **Start Early, Learn as You Go** — 30% 정보로 먼저 움직이기 (분석 과잉 경계)
- **Solve the Right Problem** — 문제 정의·분해 단계 강화
- **Align, Disagree & Commit (반대 측면)** — 뒤가 아니라 앞에서 공개적으로 반대
- **Relentless 불굴** — 환경/타이밍 탓보다 "내 가정 어디가 틀렸나" 먼저 묻기

**스타일**: 의미를 이해하면 꾸준히 몰입해서 끝까지 가는 타입. **시작 속도와 사고 투명성을 의식적으로 끌어올리는 단계**.

**직급**: 수석 엔지니어 (Senior/Staff Engineer)

**조직 구성** (총 9명):
- CEO (영업 + 금융 딜 업무 비중 높음), CTO
- 서비스개발본부 (CTO 겸 본부장, 6명):
  - 시니어: 수석 엔지니어(나), 수석 디자이너
  - 미드레벨: 개발자 2명 (경력 3~4년)
  - 주니어: AI 엔지니어 1명 (인턴급)
- 공식 PM 역할 부재 → 나(수석 엔지니어)가 모노클 AI의 사실상 PM 역할 겸임

**서비스 포트폴리오**:
- **딜매치**: 창업 서비스 (금융 딜 매칭)
- **모노클 AI**: 현재 개발 역량 집중 대상 ← 내 PM 겸임 대상
- **세이프티스냅**: 최소 대응 모드 (나는 거의 관여하지 않음)
- 2025년 4월 태스크포스 구성 → 모노클 AI + 세이프티스냅 추가 개발

**현재 팀 배치** (2026~):
- 모노클 AI (우선): 나 + CTO (핵심), 미드레벨 개발자 2명 + AI 엔지니어 (겸임)
- 세이프티스냅 (최소 대응): 디자이너 + 미드레벨 개발자 2명·AI 엔지니어가 일부 리소스 할애
- ~2025: 나+CTO=모노클, 디자이너+미드레벨 개발자 2명+AI 엔지니어=세이프티스냅으로 분리 운영

> 소규모 조직이므로 수석 엔지니어의 역할 범위가 넓다. 아키텍처 의사결정, 주니어/미드레벨 성장 지원, CTO와의 기술 방향 조율에 더해 **모노클 AI PM 역할까지 겸임**한다. CEO가 딜 업무에 집중하는 구조이므로, 제품 방향·우선순위·스펙 판단이 사실상 나에게 위임되어 있다. 올해부터 모노클 AI에 인력이 집중되면서 미드레벨·주니어 멤버와의 협업 비중이 높아졌고, 이들의 성장 지원과 업무 조율도 핵심 책임이다. 위임 대상이 제한적이므로 "무엇을 시스템화할 것인가"가 핵심 판단이다.

## 데일리 회고 프로세스

### 1단계: 저널 읽기
```bash
# KST 기준 오늘 날짜 & 요일 확인
TZ='Asia/Seoul' date '+%Y-%m-%d %a'
```
위 "저널 파일 탐색" 순서대로 해당 날짜 파일 찾아 읽기.
예: 2026-05-13 수요일이면 `~/obsidian/sb/데일리 노트/2026-05-13 수요일.md`

### 1.5단계: 당일 Claude 대화 transcript 요약 → 저널 append

**배경**: 2026-05-13부로 cowork 30분 자동화 폐지. 회고 시점에 한 번만 당일 transcript를 의미 단위로 정리해서 (a) 평가용 컨텍스트와 (b) 검색용 아카이브를 동시에 확보한다.

**1.5.1 당일 transcript 파일 수집** (KST 00:00 ~ 24:00):
```bash
TODAY=$(TZ='Asia/Seoul' date '+%Y-%m-%d')
TOMORROW=$(TZ='Asia/Seoul' date -v+1d '+%Y-%m-%d')
find ~/.claude/projects -name "*.jsonl" \
  -newermt "$TODAY 00:00:00 +0900" \
  ! -newermt "$TOMORROW 00:00:00 +0900"
```
프로젝트 디렉토리 여러 곳에 흩어져 있으므로 위 명령으로 한 번에 수집.

**1.5.2 요약은 subagent에 위임**: 메인 컨텍스트 보존을 위해 `Agent` 도구로 general-purpose subagent 호출.

서브에이전트 프롬프트에 다음을 포함:
- **입력**: 위에서 찾은 jsonl 파일 경로 목록 (절대 경로로 전달)
- **출력 목표**: 의미 단위 아크(고민→시도→효과) 블록의 markdown
- **기록 원칙** (sb 저널 규칙 그대로):
  - 시간축이 아닌 **작업 단위**로 묶기. 같은 주제는 여러 세션에 걸쳐 있어도 하나의 블록
  - **저자성 voice 분리**:
    - 현석님 인지·판단·결정 → 1인칭 능동체 ("~라고 판단", "A보다 B가 낫다고 결론")
    - 에이전트 수행 → 보고형 수동체 ("확인 결과 ~", "실행 보고: ~")
    - 에이전트가 친 bash 명령을 현석님이 친 것처럼 귀속하지 말 것
  - **블록 게이트**:
    - 고민 있음 AND 효과 확인됨 → **풀 블록** (제목 + 본문, 아카이브 대상)
    - 고민 있음 BUT 효과 미확인 → 블록 만들지 말고 **진행중·미완 1줄 bullet**로 별도 섹션
    - 고민 없는 routine 실행 → 아카이브 말미 **1줄 bullet**만
  - **검색 친화**:
    - 블록 제목 = 미래 grep용 키워드 (예: "extras 함정", "PITR 보류 결정")
    - 에러 메시지는 verbatim (code block 그대로)
    - 재사용 가능한 학습은 패턴 명명
    - 태그·wiki 링크·atomic note 승격 포인터(`→ [[...]] (승격 대상)`) 적극 사용
- **출력 형식**:
  ```markdown
  ## 아카이브 블록

  ### [블록 제목 1]
  - **[프로젝트 태그]** 본문...

  ### [블록 제목 2]
  ...

  ## 진행 중·미완
  - **[프로젝트]** 미완 항목 1줄
  ```

**1.5.3 저널에 append**:
- 저널 파일에서 `# 🗄️ 아카이브` 섹션을 찾아 그 아래에 subagent의 "아카이브 블록" 추가
- `# 📍 진행 중·미완` 섹션에는 subagent의 "진행 중·미완" 항목 추가
- 두 섹션이 없는 구식 30분 격자 포맷이면 파일 끝에 두 섹션을 새로 만들어 추가
- `# 🔭 헤드라인`은 선택 — 의미 있는 블록이 3~5개 이상이면 한 줄씩 갱신, 적으면 생략

**1.5.4 갱신된 저널 재읽기**: append된 결과 포함 다시 읽어 2단계 평가의 입력으로 사용. 평가는 **현석님 수동 기록 + transcript 요약 블록 모두**를 본다.

### 2단계: 행동 원칙 평가
저널 내용을 **행동 원칙 8개 + Spirit 2개** 기준으로 분석:
- **발휘된 원칙**: 저널에서 관찰된 행동/사건과 연결
- **개선 포인트**: 부족했던 원칙과 구체적 코칭

### 3단계: 평가 기준

**강점 원칙 체크** (유지·증폭):
- **Own the Vision**: 방향을 자기 언어로 번역해서 오늘 무엇을 다르게 했는가? 내가 만든 걸 직접 써봤는가?
- **Pursue Excellence**: 결과만 고치지 않고 가정·사고방식까지 돌아봤는가? 자기 지식 경계를 정확히 인식했는가?
- **Align, Disagree & Commit (협력 측면)**: 팀 방향 정렬에 기여했는가? 결정에 빠르게 헌신했는가?
- **Leave It Better**: 코드·문서·프로세스를 더 나은 상태로 남겼는가?

**성장 원칙 체크** (의식적 개발):
- **Start Early, Learn as You Go**: 30% 정보로도 먼저 시작했는가? 분석 과잉으로 멈춰있지 않았는가?
- **Solve the Right Problem**: 어떻게 풀지보다 무엇을 풀지부터 정의했는가? 큰 문제를 분해했는가?
- **Align, Disagree & Commit (반대 측면)**: 반대 의견을 **앞에서 공개적으로** 말했는가? 뒤에서 흔들지 않았는가?
- **Relentless 불굴**: 환경·타이밍 탓 대신 "내 가정 어디가 틀렸나"를 먼저 물었는가?

**나머지 원칙도 가볍게 스캔** (Feel the Customer, Count the Outcome, Close with Impact) — 두드러진 발휘/누락만 짚는다.

**DON'T 체크** (행동 원칙 위반 시그널):
- 반대 의견을 회의 뒤에서 말하거나, 결정을 비즈니스 일선에서 못 닫고 흔들지 않았는가?
- 일한 시간/투입을 성과의 근거로 삼지 않았는가? (output ≠ outcome)
- 간단한 일을 1~2주 붙잡는 완벽주의에 빠지지 않았는가?
- 협업에서 책임을 다음 사람에게 떠넘기지 않았는가? (Production chain 끝까지 주시)
- 나쁜 결과를 데이터로 보지 않고 환경 탓·타이밍 탓 먼저 하지 않았는가?

### 4단계: 결과 출력

사용자에게 평가 결과를 보여주고 확인 후 저널에 추가.

### 5단계: 저널에 추가

저널 파일 하단에 Daily Reflection 섹션 추가:

```markdown
---
## Daily Reflection

### 발휘된 원칙
| 원칙 | 근거 |
|------|------|
| (원칙명) | (저널에서 관찰된 행동/사건) |

### 개선 포인트
| 원칙 | 관찰 | 코칭 |
|------|------|------|
```

## 주간 회고 프로세스

### 1단계: 주간 저널 수집
```bash
# 이번 주 월~일 날짜 계산 (KST 기준)
TZ='Asia/Seoul' date '+%Y %m %d %a'
```
해당 주의 모든 저널 파일 읽기

### 1.5단계: 빈 날짜에 대해 transcript 요약 보충

데일리 회고를 매일 했다면 각 저널의 `🗄️ 아카이브`가 이미 채워져 있다. 비어있거나 누락된 날에 대해서만:

1. 그 날짜의 transcript 파일 수집 (1.5.1과 동일하되 `TODAY`를 해당 날짜로):
   ```bash
   DAY="YYYY-MM-DD"  # 대상 날짜
   NEXT=$(date -j -v+1d -f '%Y-%m-%d' "$DAY" '+%Y-%m-%d')
   find ~/.claude/projects -name "*.jsonl" \
     -newermt "$DAY 00:00:00 +0900" \
     ! -newermt "$NEXT 00:00:00 +0900"
   ```
2. 데일리 회고의 1.5.2 절차대로 subagent에 요약 위임 → 해당 일자 저널에 append
3. 한 주 안의 빈 날짜들은 subagent 호출을 **병렬로** 일괄 처리 (각 날짜별 1건씩 동시 dispatch)

### 2단계: 종합 분석
- 주간 **행동 원칙 발휘 패턴**
- 반복되는 강점/약점 (8개 원칙 중)
- 성장 원칙(Start Early / Solve the Right Problem / 반대 측면 / Relentless) 발휘 빈도
- Spirit (Relentless · Pursue Excellence) 발현 사례

### 3단계: 평가자 관점 분석

> **목적**: 행동 원칙 코칭이 "어떤 근육을 썼나"를 본다면, 평가자 관점은 "이 사람을 승진시킬 수 있나"를 묻는다. 행동 원칙 8개 + Spirit 2개 프레임만으로는 잡기 어려운 구조적 피드백을 제공한다.

**역할 기대치 기준 평가** (수석 엔지니어 / 모노클 AI 최종 기술 판단자):

수석 엔지니어에게 기대되는 행동을 기준으로 이번 주 저널을 평가한다. 코칭 톤이 아니라 **인사평가 담당자가 실제로 작성할 법한 솔직한 평가** 톤으로 작성한다. 칭찬할 건 하되, 아쉬운 점은 구체적 근거와 함께 직설적으로 짚는다.

평가 관점:

| 관점 | 체크 포인트 |
|------|------------|
| **기술 판단자 역할** | 모노클 AI 최종 기술 판단자로서 아키텍처·기술 선택·인프라 의사결정을 주도했는가? "본부장님이 하시던 걸 대신"이 아니라 "내가 최종 판단자"로서 행동했는가? |
| **팀 레벨 임팩트** | 개인 실행을 넘어 팀 전체에 영향을 미치는 행동(아키텍처 방향, 프로세스 개선, 코드/설계 리뷰)이 있었는가? 모노클 AI 합류 멤버(미드레벨·AI 엔지니어)의 기술 성장 지원은 어떠한가? |
| **주니어 흐름 전환** | 기술 검토/조언이 본부장님 대신 나에게 오도록 접점을 의식적으로 구축했는가? |
| **위임 판단** | "내가 직접 안 해도 되는 일"과 "나만 할 수 있는 일"을 구분했는가? 반복 업무를 가이드/시스템으로 전환하려는 시도가 있었는가? (Leave It Better) |
| **장애 대응 총괄** | 장애·이슈에 대해 원인 분석→조치→리포팅의 최종 책임자로서 행동했는가? |
| **시간 배분** | 모노클 AI(우선) vs 세이프티스냅(최소 대응) vs 딜매치 간 리소스 배분이 전략적 우선순위와 일치하는가? 기능 구현, 도구 최적화, 기술 리더십, 멤버 지원 간 균형은 적절한가? |
| **미완료 과제 관리 (Close with Impact)** | 목표 대비 완료율은 어떠한가? 작게 쪼개서 닫았는가, 아니면 큰 덩어리를 못 닫고 끌었는가? 미완 항목 위임/일정 조정 판단이 있었는가? |
| **Business Impact (Count the Outcome)** | 결과물이 고객 행동·매출·실제 문제 해결로 이어졌는가? 기능 완성/문서 제출에 그치지 않았는가? |
